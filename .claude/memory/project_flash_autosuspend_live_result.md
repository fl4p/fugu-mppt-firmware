Branch flash-autosus (/tmp/dawn worktree). On 2026-11-12 flat ran b74f46b with auto-suspend active: 20 set-config writes gave worst RT loop gap 151.6 ms (baseline 2.6 ms) and `adc_esp32: no ADC samples for 372 ms` + ADC stall reset. Caches-off fallback measured 67 ms on the same board. The boot self-test (8 cache misses = 2066 us, ~260 us/miss from tsus 130 us x2) does not predict this: under load both cores miss continuously and misses serialize on SPI0.

**Why:** the RT loop is not cache-resident; it does blocking I2C (Arduino Wire + IDF i2c_master), FreeRTOS queue calls (IDF 6 puts FreeRTOS in flash unless CONFIG_FREERTOS_IN_IRAM), all in flash.

**How to apply:** goal is <1 ms loop stall during writes. Tooling: CONFIG_FUGU_WITH_RTPROF (core-1 stack sampler, `rtprof` / `rtprof clear`), `etc/rtprof_map.py <log> <elf> --min 20 --lf main/rt_iram.lf` generates the noflash fragment. Night idle hot set = 67 fns / ~40 KB IRAM (DIRAM 48%→61%). Need a profile while converting before the final list; then retest writes with auto-suspend active. flat was left on c7065aa (rtprof build, caches-off) on 11-12 19:00.

**11-13 converting profile:** 5 h on flat (c7065aa, archived ELF sha 013712c8). >=1 sample/s = 86 fns / 44 KB, plus the night set = 84 entries (ca76e94, rt_iram.lf). DIRAM same tree: base 165.6 KB; IRAM set +47.5 KB; Wi-Fi IRAM opts off -17.9 KB; net +29.6 KB vs today. That leaves ~26-32 KB free heap, and OTA min-ever (26.6 KB) would hit ~0, so it is too big as is. Biggest items: loopRT 8.8 KB and MpptController::update 6.9 KB (mostly cold branches), I2C/INA226 stack ~5 KB. The test build (build-as2) needs the self-test stall limit raised to 3000 (uncommitted), because the self-test always measures ~2066 us.
