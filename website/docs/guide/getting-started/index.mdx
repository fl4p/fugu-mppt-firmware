# Getting Started

Bringing up a board takes three steps:

1. Build and flash the firmware.
2. Flash the board configuration ([provisioning](provisioning.md)).
3. Connect to the console and join Wi-Fi.

## Quick start

The following commands build, flash, and provision a Fugu2 board connected over USB, then open the console. They
need [ESP-IDF 5.5 installed](#install-esp-idf) and exported:

<Tabs groupId="os">
<TabItem value="unix" label="macOS / Linux" default>

```bash
git clone --recursive https://github.com/fl4p/fugu-mppt-firmware
cd fugu-mppt-firmware
export ESPPORT=/dev/ttyACM0           # macOS: /dev/cu.usbmodem…
idf.py set-target esp32s3
idf.py -p $ESPPORT flash
python -m pip install littlefs-python # needed by provision.py
./provision.py fmetal                 # board configuration
python3 etc/fugu_console.py -p $ESPPORT     # interactive console
```

</TabItem>
<TabItem value="windows" label="Windows">

Run these commands in the **ESP-IDF 5.5 PowerShell** (the Start menu shortcut that the installer creates), from the
folder where you keep projects:

```powershell
git clone --recursive https://github.com/fl4p/fugu-mppt-firmware
cd fugu-mppt-firmware
$env:ESPPORT = "COM5"                 # see Device Manager → Ports (COM & LPT)
idf.py set-target esp32s3
idf.py -p $env:ESPPORT flash
python -m pip install littlefs-python # needed by provision.py
python provision.py fmetal            # board configuration
python etc\fugu_console.py -p $env:ESPPORT  # interactive console
```

Use a short project folder such as `C:\src`, because deep build paths can exceed the Windows path length limit. The ESP32-S3 USB port uses the USB CDC driver built into Windows 10 and 11.

:::note
The Windows steps follow Espressif's Windows tooling and haven't been tested on Windows yet. Reports are welcome.
:::

</TabItem>
</Tabs>

:::note
Keep the panel and battery disconnected until the board is provisioned. `flash` writes the bootloader, the
partition table, the firmware, and a mock-ADC configuration, which `provision.py` then replaces. For later firmware
updates, use `app-flash`, which keeps the configuration.
:::

To join Wi-Fi, enter these commands in the console:

```
wifi-add <ssid>:<password>
restart
```

## Install ESP-IDF

The firmware needs ESP-IDF v5.5 or newer. Install it by following Espressif's
[Get Started guide](https://docs.espressif.com/projects/esp-idf/en/v5.5/esp32s3/get-started/index.html), or use the
steps for your operating system.

<Tabs groupId="os">
<TabItem value="unix" label="macOS / Linux" default>

These commands clone ESP-IDF v5.5, install it for the `esp32s3` target, and export its environment:

```bash
git clone -b v5.5 --recursive https://github.com/espressif/esp-idf.git esp-idf-v5.5
cd esp-idf-v5.5
./install.sh esp32s3
. ./export.sh
```

Source `export.sh` in every new shell before running `idf.py`.

</TabItem>
<TabItem value="windows" label="Windows">

Use the [ESP-IDF Windows Installer](https://dl.espressif.com/dl/esp-idf/) and select ESP-IDF v5.5 with the
`esp32s3` target. The installer installs Git, Python, and the toolchain. It also adds **ESP-IDF 5.5 PowerShell** and
**ESP-IDF 5.5 CMD** shortcuts that open a shell with the environment exported.

To install manually from a clone of ESP-IDF, run `install.ps1 esp32s3`, then run `. .\export.ps1` in every new
PowerShell. In CMD, use `install.bat` and `export.bat` instead.

</TabItem>
</Tabs>

:::tip
ESP-IDF creates its own virtual environment from the system's default `python`. If the IDF installer fails on your
Python version, see [espressif/esp-idf#12322](https://github.com/espressif/esp-idf/issues/12322).
:::

## Build

On the first build, the IDF component manager downloads the components the firmware depends on, including
[arduino-esp32](https://github.com/espressif/arduino-esp32) and the OTA-over-BLE receiver
[esp-ota-ble](https://github.com/fl4p/esp-ota-ble), into `managed_components/` of your checkout. The build machine therefore
needs internet access.

The build command depends on the target:

| Target | Command |
|---|---|
| ESP32-S3 (default) | `idf.py set-target esp32s3 && idf.py build` |
| classic ESP32 | `idf.py -B build-esp32 -D SDKCONFIG=build-esp32/sdkconfig set-target esp32 && idf.py -B build-esp32 -D SDKCONFIG=build-esp32/sdkconfig build` |

Use a separate build directory and `sdkconfig` for each target. For details, see
[ESP32 variants](../hardware/esp32-variants.md#quick-start).

Optional features, such as BLE, networking, and the MCPWM driver, are Kconfig options. See
[Build Options](build-options.md).

## Flash

Two commands write the firmware to the device. They differ in what they write:

| Command | Writes |
|---|---|
| `idf.py -p $ESPPORT app-flash` | Application only; keeps the board configuration |
| `idf.py -p $ESPPORT flash` | Bootloader, partition table, application **and** the littlefs image selected in `CMakeLists.txt` (`config/lab/dry_mock` on ESP32-S3, `config/fugu1/fugu1_esp32` on ESP32) |

:::warning
`idf.py flash` overwrites the configuration partition with the board image selected by `FUGU_LITTLEFS_SRC` in the
top-level `CMakeLists.txt` (a mock-ADC configuration by default). On a configured device, use `app-flash`, or point
`CMakeLists.txt` at the right board first.
:::

`flash` and `app-flash` archive the build ELF under `elf-archive/` so that coredumps can be decoded later. See
[Debugging](../../development/debugging/index.md). To name the device, use `FUGU_DEVICE=<name> idf.py flash` or
`./flash.sh <name>`.

## Connect

`etc/fugu_console.py` talks to the device over any transport. These examples show common invocations:

```bash
python3 etc/fugu_console.py -p /dev/cu.usbmodem1101        # serial
python3 etc/fugu_console.py --ip <device-ip>               # telnet
python3 etc/fugu_console.py --ble                          # BLE (NUS)
python3 etc/fugu_console.py -p $ESPPORT -c status -c sensor  # one-shot commands
```

With no arguments, it scans all transports for devices. [Console](../../reference/console.md) documents the command
set.

Once Wi-Fi is up, telnet, FTP, MQTT, and telemetry start automatically if they're enabled in their
[configuration files](../../reference/config/index.md).

## Next steps

- Set battery and charger parameters in [`charger.conf`](../../reference/config/charger.md).
